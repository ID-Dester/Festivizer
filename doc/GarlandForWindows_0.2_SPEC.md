# Garland for Windows — ТЗ версии 0.2

**Версия документа:** 1.0.  
**Дата:** 09.11.2026.  
**Статус:** задание на следующую реализацию; функции 0.2 ещё не реализованы.  
**Платформа:** Windows 11 x64, штатная нижняя Taskbar, один монитор.  
**Стек:** C#, .NET 10, WPF и Win32 P/Invoke; Windows Forms допускается для существующего трея.

## 1. Цель и исходное состояние

Сделать прототип удобным для повседневного использования: устранить выявленные дефекты, добавить небольшое окно настроек, независимое включение декораций, темы, яркость, скорость Twinkle, сохранение и добровольный автозапуск.

Основание — [проверка 0.1](../docs/Review_0.1.md) и [общая спецификация / MVP 0.1](GarlandForWindows_SPEC.md). Успешные сборки и частичные GUI-проверки 0.1 не означают закрытия всех прежних требований. Незавершённые обязательные сценарии включить в регрессионную приёмку 0.2.

При разработке 0.2 этот документ определяет новый функциональный объём. Требования исходного ТЗ к невмешательству во ввод, отказам, fullscreen, автоскрытию и независимости декораций сохраняются. Стартовый промпт части III старого документа относится только к историческому заданию 0.1.

## 2. Объём и порядок работы

| Этап | Результат | Основание |
|---|---|---|
| A. Стабилизация | Безопасная обработка отказов overlay, DPI, проверенная политика Z-order и fullscreen | R01–R03, R05 из отчёта |
| B. Обновления и рисунок | Объединение событий, кэш геометрии, отсутствие лишних аллокаций статичных ресурсов | R04, R06 |
| C. Настройки | Модель, чтение/запись, WPF-окно и команды трея | Новый объём 0.2 |
| D. Автозапуск | Управление запуском для текущего пользователя | Новый объём 0.2 |
| E. Приёмка | Автотесты, реальные GUI-сценарии, замеры, автономная публикация и документы | Обязательные условия выпуска |

Стабилизацию выполнить до подключения новых пользовательских функций. Наличие окна настроек не компенсирует неисправный click-through, потерю трея или оставшийся поверх чужого окна overlay.

## 3. Обязательная стабилизация

### 3.1. Отказы Win32 и независимость декораций

- Проверять результаты установки стилей, позиционирования, чтения геометрии, регистрации сообщений и hooks. Сохранять last-error только для API, которые его документируют; для DWM использовать HRESULT.
- Для `Get/SetWindowLongPtr` корректно различать допустимый нулевой результат и ошибку. Стили click-through/non-activation подтвердить до первого показа overlay. При неудаче скрыть или закрыть его, не показывать потенциально перехватывающее ввод окно.
- При сбое позиционирования не оставлять декорацию на прежних координатах. Разделить обработку отказов Taskbar и оконной рамки, включая отрисовку/анимацию: ошибка одной не должна завершать весь host.
- Не продолжать бесконечные попытки на каждом кадре. Ограничить повторные попытки и частоту одинаковых логов; восстановление разрешать после подходящего события или недорогой резервной сверки.
- Безопасно освобождать частично созданные ресурсы. Снимать hooks в потоке регистрации, проверять результат, удерживать callback до окончания использования. Повторный `Dispose` безопасен.
- Ошибка закрытия одного ресурса не должна помешать попыткам освободить остальные ресурсы.

### 3.2. Координаты и DPI

- Геометрию чужих окон и монитора хранить в физических экранных координатах; размеры рисунка, шаг ламп, отступ и толщину — в DIP. Преобразовывать размеры при передаче в Win32 с учётом DPI overlay.
- Убрать зависимость «30 физических пикселей высоты против минимальных 20 DIP» и согласовать внешний отступ рамки с координатами рисунка.
- При 100%, 150%, 175% и 200% Taskbar-гирлянда остаётся видимой, размер ламп визуально согласован с масштабом, рисунок и свечение не обрезаются границами overlay.
- При смене масштаба/разрешения обновлять прямоугольники и кэш рисунка. Не добавлять полноценную поддержку нескольких мониторов в этом выпуске.

### 3.3. Z-order, фильтрация и fullscreen

- Заменить обещание «непосредственно над HWND» проверенной политикой размещения. Описать выбранный алгоритм и ограничения в документации; повторный `HWND_TOP` сам по себе не доказывает привязку к цели.
- Для 0.2 topmost-цели явно исключать из украшения рамкой; не делать оконный overlay глобально topmost. Их fullscreen-состояние проверять независимо от исключения рамки.
- Проверить обычные окна, перекрывающие popup, owned-диалоги, Alt+Tab и потерю foreground. После смены цели скрывать старую рамку до показа новой; не допускать декоративных копий.
- Разделить распознавание собственных/служебных поверхностей, fullscreen-конфликта и допустимости рамки. Общий класс `Windows.UI.Core.CoreWindow` не считать достаточным доказательством принадлежности оболочке.
- Сохранить исходную базовую fullscreen-эвристику: `rcMonitor`, допуск 2 физических пикселя на каждой стороне, отсутствие `WS_CAPTION` и `WS_THICKFRAME`; maximized с обычной рамкой скрывает только оконную гирлянду.
- После выхода из fullscreen заново оценивать настройки, foreground и видимость Taskbar. Пропуски эвристики указывать с конкретными проверенными приложениями; не обещать все игры/плееры.

### 3.4. Автоскрытие Taskbar и восстановление оболочки

- **Скрывать гирлянду вместе с панелью задач**, полностью убирая провод, лампы и свечение; возвращать при появлении панели по актуальной геометрии.
- Учитывать запуск с уже скрытой панелью, изменение режима автоскрытия и новые настройки включения. Не удерживать панель открытой и не мешать её вызову у края экрана.
- Автоскрытие панели не отключает рамку допустимого активного окна.
- После `TaskbarCreated` восстанавливать одну иконку трея, меню, команды и геометрию; сохранять все текущие настройки, включая общий выключатель. Восстановление работает и при всех скрытых overlay.

### 3.5. Очередь событий и производительность

- Объединять запросы обновления до постановки операции в Dispatcher с учётом вызовов из разных потоков. В очереди не должно копиться по отдельной операции на каждый WinEvent.
- Перед выполнением отложенной операции проверять завершение приложения, действующие настройки и актуальный foreground. Устаревшее обновление не возвращает скрытую рамку.
- Отделить события обнаружения от кадров анимации; сохранить ограниченную резервную сверку. Таймеры, не нужные при выключении/скрытии, останавливать; механизм восстановления после изменения среды должен оставаться работоспособным.
- Кэшировать путь провода, позиции ламп и подходящие графические ресурсы. Перестраивать кэш при изменении размера, DPI или темы; каждый кадр меняет только зависящие от времени параметры.
- Ограничить анимацию максимум 30 обновлениями в секунду; зависимость от времени сохранить. Скорость мерцания не должна изменять частоту опроса окон.

## 4. Окно настроек и системный трей

Окно настроек — обычное интерактивное **WPF-окно**. Оно может принимать фокус и ввод; требование non-activation относится к декоративным overlay. Собственные окна приложения не декорировать.

Трей содержит:

1. `Включить/выключить гирлянды` — общий сохранённый выключатель.
2. `Панель задач` — независимый пункт с отметкой.
3. `Рамка активного окна` — независимый пункт с отметкой.
4. `Настройки…` — открыть существующее окно или создать единственное новое.
5. `Выход` — завершить приложение с освобождением ресурсов.

В окне настроек показать два независимых переключателя, выбор темы, яркость, скорость и автозапуск. Кнопки: `Применить`, `Отмена`, `По умолчанию`. Закрытие окна настроек не завершает приложение.

- Изменения в окне редактируют черновик; `Применить` валидирует, сохраняет и применяет значения без перезапуска overlay. `Отмена` и закрытие окна отменяют неприменённый черновик.
- `По умолчанию` заполняет черновик безопасными значениями; запись происходит только по `Применить`.
- Изменения пунктов трея применяются и сохраняются сразу. Если окно настроек открыто, синхронизировать соответствующие переключатели черновика с трей-командой, сохранив остальные неприменённые поля. Не позволять устаревшему черновику отменить последнюю команду трея.
- Общий выключатель не меняет два независимых переключателя: повторное включение восстанавливает выбранную комбинацию. Текст и отметки меню отражают фактические значения.
- Для настроек выбранная тема общая для двух гирлянд; отдельное оформление каждой оставить на будущие версии.

Видимость вычислять раздельно:

```text
TaskbarVisible = GarlandsEnabled && TaskbarEnabled && PanelVisible && !FullscreenConflict && TaskbarHealthy
FrameVisible   = GarlandsEnabled && WindowFrameEnabled && EligibleForeground && !FullscreenConflict && FrameHealthy
```

`EligibleForeground` включает restored-состояние и исключает собственные окна, служебные поверхности и topmost-цели. Положение/геометрия также должны быть валидны. Настройки пользователя и временное скрытие по состоянию Windows — разные данные: fullscreen и автоскрытие не перезаписывают сохранённые переключатели.

## 5. Темы, яркость и скорость

В 0.2 сохранить один вид анимации — `Twinkle`. Предусмотреть четыре встроенные палитры без редактора и загрузки пользовательских ресурсов:

| Идентификатор | Название в UI | Палитра ламп |
|---|---|---|
| `classicChristmas` | Классическая | `#FF4137`, `#46E16E`, `#FFD22D`, `#4196FF` |
| `warmWhite` | Тёплый белый | `#FFE1A6` |
| `coldWhite` | Холодный белый | `#DCEEFF` |
| `multicolor` | Разноцветная | `#FF4137`, `#FF923D`, `#FFD22D`, `#46E16E`, `#4196FF`, `#BE78FF` |

Значения — начальные цвета для реализации; допустима небольшая визуальная корректировка с записью итоговой палитры в документацию. Форма ламп и провод при смене темы сохраняются.

- Яркость: **10–100%**, по умолчанию **100%**. Общий множитель влияет на лампу и свечение, не на прозрачность всего окна и не на click-through. Выключение доступно отдельными переключателями.
- Скорость: **25–200%**, по умолчанию **100%**. Это множитель времени Twinkle; ограничение кадров не меняется. Применение скорости не должно вызывать резкую вспышку или сброс всей геометрии.
- Проверить крайние значения, обе гирлянды и комбинации тем; плавное мерцание без резких вспышек сохраняется.

## 6. Хранение настроек

Путь: `%AppData%\GarlandForWindows\settings.json`. Не зависеть от текущей рабочей папки. Для сериализации достаточно `System.Text.Json`.

Начальная схема:

```json
{
  "schemaVersion": 1,
  "garlandsEnabled": true,
  "taskbarEnabled": true,
  "windowFrameEnabled": true,
  "theme": "classicChristmas",
  "brightnessPercent": 100,
  "speedPercent": 100
}
```

- При первом старте использовать эти значения. Загружать настройки до первого показа overlay, чтобы не мигали ранее выключенные гирлянды.
- Отсутствующие поля заполнять defaults, неизвестные поля текущей схемы игнорировать, неизвестную тему заменять стандартной. Числа вне диапазона ограничивать ближайшей границей; неверные типы/повреждённый JSON обрабатывать без падения.
- Повреждённый файл по возможности сохранить как одну резервную копию `settings.invalid.json`, затем использовать defaults. Если копирование недоступно, записать ограниченное предупреждение; не зацикливаться.
- Не перезаписывать файл с более новой `schemaVersion`: использовать defaults в памяти, показать сообщение о несовместимой версии и запретить сохранение до явного сброса пользователем. Сброс не меняет состояние автозапуска без применения соответствующего поля.
- Записывать через временный файл в той же папке с последующей заменой. Не оставлять обрезанный основной JSON при сбое записи.
- При неудаче сохранения оставить предыдущие применённые значения; в окне настроек сохранить черновик и показать понятную ошибку. Для команды трея откатить отметку и сообщить о невозможности сохранения. Не выдавать ошибку за успешное применение.
- Не сохранять настройки на каждом кадре, движении окна или изменении фазы анимации. Дополнительные настройки и versioned-схема не требуют отдельной БД.

## 7. Автозапуск

Автозапуск **выключен по умолчанию** и включается только явным выбором пользователя. Реализация не должна сама включать его при разработке или проверке других функций.

- Использовать значение `GarlandForWindows` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, без администратора, служб и планировщика.
- Записывать полный путь текущего exe в кавычках; проверять ограничения длины команды и корректную работу пути с пробелами. Не использовать `dotnet run`, путь solution или текущую рабочую папку.
- Приложение остаётся портативным: для автозапуска из публикации требуется вся папка self-contained, а не один exe. Если приложение перемещено, показывать несовпадение пути и предлагать обновить собственную запись только по явному применению настройки.
- При выключении удалять только собственное значение. Не изменять другие записи пользователя.
- Источник фактического состояния — собственная запись Run; отдельный флаг в `settings.json` не хранить. Не восстанавливать удалённую пользователем запись автоматически. Не обходить системное отключение автозапуска; запись Run означает регистрацию, а не гарантию запуска Windows.
- Отказ чтения/изменения реестра не завершает приложение. Показывать статус «недоступно» или ошибку; не утверждать, что автозапуск включён.
- При `Применить` сначала сохранять обычные настройки; затем применять изменение автозапуска. Если реестр недоступен, остальные сохранённые настройки остаются применены, а UI явно показывает неудачу автозапуска и его фактическое состояние.
- Сброс defaults задаёт в черновике автозапуск «выключен», но меняет Run только после `Применить`. Обычный выход из приложения не удаляет регистрацию автозапуска.

## 8. Разделение ответственности

Не переписывать приложение на WinForms и не добавлять большой фреймворк. Сохранить один WPF-проект и существующий небольшой тестовый проект; при необходимости расширить набор тестов без обязательного перехода на новый раннер.

Выделить из `ApplicationHost` небольшие компоненты по ответственности:

- `WindowTracker` / `WindowEligibilityPolicy` / `FullscreenDetector` — сбор фактов и решения о цели.
- `TaskbarTracker` — геометрия, автоскрытие и восстановление оболочки.
- `OverlayManager` — показ, скрытие, безопасные стили, Z-order и изоляция отказов.
- `TrayService`, `SettingsService`, `AutoStartService` — команды и пользовательские предпочтения.
- Модель настроек, описание палитры и кэш рисунка — отдельно от P/Invoke.

Названия и число файлов можно уточнить при реализации; не создавать пустые абстракции. Важно, чтобы настройки, Win32 и отрисовка не расширяли один монолитный host. В interop заменить значимые магические числа именованными константами, особенно `WINEVENT_OUTOFCONTEXT`, атрибуты DWM и appbar-сообщения.

## 9. Проверки и приёмка

### 9.1. Автоматические проверки

- Сборки Debug/Release, сохранение существующих 12 проверок fullscreen.
- Fullscreen: допуск внутрь и наружу на каждой стороне, `rcMonitor` против `rcWork`, стили и maximized/topmost как независимые признаки допуска рамки.
- Таблица видимости: комбинации общего и независимых переключателей, временного автоскрытия/fullscreen и неисправности одного overlay.
- Настройки: round-trip, отсутствие файла, повреждение, неверные типы/диапазоны, неизвестные поля/тема, более новая схема, отказ записи с сохранением предыдущего файла/состояния.
- Независимая DPI-геометрия и размер полосы при 100%, 150%, 175%, 200%; отсутствие обрезания рассчитываемых границ рисунка.
- Ошибки interop и частично неудачный запуск через узкий тестовый адаптер: отказ установки стилей, позиционирования и снятия hook; в рабочем приложении не подменять реальные окна заглушками.
- Проверить объединение потока запросов и отмену устаревших обновлений без искусственных таймерных задержек в тестах.
- Автозапуск: формирование команды, путь с пробелами, отключение только собственного значения, отказ доступа. Автотесты не должны менять реальную запись Run текущего пользователя.

### 9.2. Ручная матрица Windows 11

Каждую строку отметить результатом и средой; неподтверждённые сценарии не помечать пройденными.

| Область | Обязательные сценарии |
|---|---|
| Ввод | Клики через лампы/свечение на Taskbar, кнопках окна и resize-границах; клавиатура и фокус остаются у приложения |
| Окна | Проводник и один названный браузер: move/resize, minimize/close/maximize/restore, Alt+Tab; popup и topmost-цель |
| Taskbar | Автоскрытие и возврат; запуск при скрытой панели; смена режима во время работы |
| Fullscreen | Хотя бы одно borderless-приложение и одно браузерное fullscreen-видео; вход/выход, maximized не равен fullscreen |
| Дисплей | 100%, 150%, 175%, 200% и смена разрешения на одном мониторе; видимость, размеры и геометрия корректны |
| Explorer | Перезапуск при общем включении/выключении и при выключенной одной декорации; одна иконка, рабочие команды и сохранённые значения |
| Настройки | Единственное окно, Apply/Cancel/Defaults, сочетание с командами трея, все темы, крайние яркость/скорость, перезапуск приложения |
| Автозапуск | По явному согласию при приёмке: включить, проверить вход пользователя, отключить, убедиться в удалении только своей записи; учесть отключение Windows |
| Жизненный цикл | Второй экземпляр, штатный выход из трея, частичный отказ запуска, 100 переключений и 30 минут работы |

Изменения системного масштаба, перезапуск Explorer и реальный вход пользователя проводить в согласованном тестовом сеансе; не выдавать их за результат одного визуального smoke-теста.

### 9.3. Замеры и итоговые артефакты

- Сравнить 0.1 и 0.2 на одном оборудовании: обе гирлянды, только Taskbar, только рамка, всё скрыто; указать разрешение, DPI, период измерения, среднюю загрузку CPU, working set/private bytes и характер аллокаций.
- После прогрева проверить отсутствие неконтролируемого роста памяти за 30 минут. Цели исходного ТЗ (<1% CPU, около 80 МБ RAM) остаются ориентирами; фактические цифры обязательны, превышение объяснить.
- Подготовить self-contained Release win-x64 с версией приложения 0.2.0 и проверить запуск всей папки на чистой Windows 11 без установленного .NET. Single-file необязателен.
- Обновить README, архитектурное описание и KnownLimitations; добавить отчёт по состояниям «код написан / сборка / проверка с результатом / принято» и список конкретных GUI-проверок.
- Предупреждение NuGet о недоступности аудита не скрывать и не интерпретировать как пройденную проверку уязвимостей.

**0.2 принимается**, когда пройдены обязательные проверки этого документа и регрессионные требования 0.1, устранены блокирующие дефекты ввода/видимости/завершения и подготовлены артефакты. Непройденные обязательные сценарии блокируют приёмку; список ограничений не отменяет требования.

## 10. За пределами 0.2

Не добавлять украшение «Пуска», всех окон одновременно, maximized-рамок, полноценную поддержку нескольких мониторов, новые типы анимации, редактор тем, снег/звук/частицы, установщик, автообновление, сеть, аккаунты и телеметрию. Не внедряться в чужие процессы и не требовать администратора.
