# 0.2.3 — рабочий отчёт о проверке

**Состояние: не принято; финальный кандидат ещё не опубликован.** Подготовлена отдельная диагностическая сборка для воспроизведения CS2. Отчёт фиксирует промежуточную работу, а не завершение требований [ТЗ](../doc/GarlandForWindows_0.2_Finalization_SPEC.md).

## Код написан

- Начата классификация popup-наблюдений: устойчивое противоположное состояние и недостоверное чтение различаются; записываются переходы. Изменены ожидание фоновой отмены и независимость шагов уборки. V01/V02 пока не закрыты: требуется проверка полной popup-оркестрации и отказов через адаптеры, включая доказательство работы всех ветвей отмены и уборки.
- Добавлена разрабатываемая обёртка `tests/Run-DesktopSupervisor.ps1`, отдельная сводка и промежуточная фаза дочернего теста. Проверка независимой остановки выполнена на тестовом режиме без окна; полный набор отрицательных и временных проверок supervisor остаётся открытым.
- Для диагностики fullscreen добавлены журналирование физических границ и их источника, монитора, DPI, стилей, состояния и видимости без заголовков и содержимого окон; одинаковые записи ограничены по частоте. Версия приложения изменена на 0.2.3. Подтверждённого исправления CS2 нет: дефект ещё не воспроизведён, причина не установлена. Историческое сообщение: Festivizer 0.2 и CS2; версия игры и точный режим окна не подтверждены.

## Предварительное исправление CS2 и сборка для проверки

После сообщения пользователя о сохранении дефекта журнал диагностической сборки зафиксировал окно с физическими границами `0,0,3440,1440`, равными `rcMonitor`, и стилем `0x96CA0000`, содержащим `WS_CAPTION`. Поэтому базовый критерий без заголовка возвращал `fullscreen=false`, а обе гирлянды оставались видимыми. Сопоставление этого окна с CS2 основано на времени проверки и сообщении пользователя; PID окна к моменту проверки уже завершился, поэтому прямое подтверждение имени процесса отсутствует.

Добавлено узкое правило для процесса `cs2`, точного наблюдавшегося стиля, не-maximized окна и границ монитора с прежним допуском 2 px. При невозможности прочитать имя процесса в этом конкретном сочетании фактов применяется безопасное скрытие. Иные стили и процессы не получают исключение; для обычного maximized-окна сохраняется прежняя политика. Правило требует подтверждения на реальной CS2 и не считается универсальным исправлением для других игр или режимов.

Сборки Debug и Release выполнены, логические тесты обеих конфигураций завершились с кодом 0. После последнего изменения кода выполнена серия из пяти Debug и пяти Release через supervisor: все 10 дали PASS/0; журналы находятся в папках `desktop-20261110-152617-*` — `desktop-20261110-152626-*` в `artifacts/validation/0.2.3/`. Эта серия не закрывает ещё отсутствующие требования V01/V02/C01.

Self-contained сборка для проверки CS2: `artifacts/publish/win-x64-0.2.3-candidate-20261110-cs2/`, манифест `artifacts/validation/0.2.3/candidate-20261110-cs2-manifest.json`. SHA-256 exe `3D9026C397DE17FF78E06B76346EB7424F50D72AF6AD5BAC194343CB2BFF69E8`, production DLL `8628A4D54A8A1E5D8E36CE8359C792E45C766801A2B3BC27293ACB89B6BBEB58`. Совпадение хеша exe с диагностической сборкой не идентифицирует DLL: проверять необходимо оба хеша запущенного экземпляра. На момент составления новая сборка ещё не запущена; прежний диагностический экземпляр следует штатно завершить перед её запуском. Реальная проверка CS2 — NOT_RUN.
