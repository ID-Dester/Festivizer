# Отчёт о стабилизации проверки 0.2.2 — 10.11.2026

**Статус:** стенд и карта покрытия подготовлены; автоматическая серия текущего стенда прошла. **Приёмка 0.2.2 не завершена:** ручная матрица на идентифицированной публикации не выполнена, ряд сквозных и негативных сценариев остаётся открытым в карте покрытия.

## Стенд и диагностика

DesktopTests проверяет доступность default input desktop до создания окон и возвращает SKIP с кодом 2 при недоступности. Результат `Activate()` записывается отдельно от фактического foreground; ожидание условия использует `Stopwatch`, 5 секунд и асинхронный интервал 40 мс. `--interactive` позволяет выбрать собственное тестовое окно в течение 60 секунд. Отсутствие или потеря предусловия помечаются BLOCKED, а попадание фокуса на overlay — FAIL. Итоговые коды: 0 PASS, 1 FAIL, 2 SKIP, 3 BLOCKED; FAIL имеет приоритет.

Открытие и закрытие popup проверяются по состоянию Windows; предусмотрены ограничение времени, отмена собственного меню и отдельные попытки очистки ресурсов. Для каждого прогона создаётся `artifacts/validation/0.2.2/<run-id>/` с `stdout.txt`, `stderr.txt`, `summary.json`: версия/хеш тестовой DLL, PID, ОС, SDK/runtime, время, результаты, сведения о foreground и уборке, хеши исходников. Детерминированные тесты с подставным временем проверяют ожидание, классификацию, deadline и приоритет итогового кода. Они не являются полным моделированием всех сбоев реального popup и его очистки.

### Замечания к стенду

1. **[P2] Таймаут подтверждения Closed ошибочно сводится к BLOCKED.** `tests/GarlandForWindows.DesktopTests/Program.cs:96–101`, `ValidationWait.cs:18`. Если desktop доступен, foreground остаётся у правильной цели, а чтение меню устойчиво возвращает Open, проверка выдаёт Waiting, затем общий helper возвращает Blocked по дедлайну. Результат popup становится BLOCKED/exit 3, хотя предусловия сохранены и не выполнено проверяемое поведение. Следует отделить потерю предусловий/недостоверное чтение от подтверждённого незакрытого меню; для последнего нужен FAIL/exit 1. Добавить детерминированные сценарии именно этой ветки интеграции popup, включая сохранённый foreground и Open до дедлайна. Замечание получено анализом ветвления; в положительном GUI-прогоне отказ не возникал.

2. **[P2] Резервная отмена popup не обеспечивает предельное время завершения процесса.** `tests/GarlandForWindows.DesktopTests/Program.cs:86–88`, `NativeMenu.cs:21`. После 5,5 секунды фоновая задача однократно вызывает `PostCancelMode`, но результат отправки игнорируется; задача не ожидается. Сам `TrackPopupMenu` вызывается синхронно, а `finally` и запись итоговой сводки выполняются после его возврата. При неуспешной отправке либо необработанной отмене нет следующего шага, который ограничит время процесса и сохранит итог отказа. Отправка через [PostMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew) асинхронна и сама по себе не подтверждает обработку сообщения. Нужны наблюдаемый результат отмены и независимый ограничитель времени процесса DesktopTests с сохранением диагностики; при принудительном завершении затрагивать только собственный запущенный тестовый процесс. Проверить отказ отправки/необработанную отмену через адаптеры. Фактического зависания в выполненных положительных прогонах не наблюдалось.

Оба замечания относятся к выполнению §2.3 и §3 ТЗ стабилизации стенда. Успешные прогоны остаются действительными; для закрытия доработки требуется подтвердить также отрицательные пути. Ручная матрица, недостающие сквозные сценарии карты и ранее зарегистрированный borderless fullscreen остаются отдельными открытыми пунктами.
