## Повторный аудит исходников — рамка за окном

Проверка 09.11.2026 выполнена по текущей рабочей папке после добавления повторного позиционирования за `Show()`. Исходники приложения в рамках этого аудита не изменялись.

### Результаты новых проверок

- `dotnet build GarlandForWindows.sln -c Release --no-restore --nologo` — успешно, 0 ошибок, 1 предупреждение NU1900 из существующего восстановления NuGet. Первая попытка в ограниченной среде была отменена компилятором; повторная сборка вне песочницы прошла.
- `dotnet tests/GarlandForWindows.Tests/bin/Release/net10.0/GarlandForWindows.Tests.dll` — код выхода 0, 61 строка PASS. Таблица видимости внутри набора дополнительно перебирает комбинации состояний.
- Новые GUI-прогоны, смена системного DPI и запуск игры в этом аудите не проводились; прежние результаты пользователя сохранены выше. Debug и публикация заново не проверялись.

### Выводы по реализации

1. **F01 — P1: не обеспечен инвариант «рамка выше цели».** `ApplicationHost.Refresh` передаёт в `frame.Place` только геометрию и общий `HWND_TOP` (строка 152 на момент аудита). `GarlandOverlay` не хранит целевой HWND/owner, `OverlaySafety.Place` проверяет успех API, но не относительный порядок окон. Это подтверждённый пробел реализации и открытое наблюдение пользователя; точная причина конкретного эпизода без трассировки не установлена.
2. **F02 — P2: свой foreground отбрасывается до обновления.** В `OnWinEvent` проверка собственного PID предшествует проверке `EVENT_SYSTEM_FOREGROUND` (строки 111–123). При активации настроек рамка предыдущей цели может оставаться до следующей резервной сверки. Это объясняет задержку обработки собственного foreground, но само по себе не доказывает причину устойчивой рамки за окном.
3. **F03 — P2: DPI-обработчик обновляет только рисунок.** `GarlandOverlay.DpiChanged` инвалидирует кэш (строка 26), не запрашивая согласованную проверку bounds/Z-order после перехода. Геометрия и размещение исправляются другими событиями/сверкой; отдельный переход жизненного цикла не выражен и не проверяется.
4. **F04 — пробел тестирования.** `FakeOverlayInterop.TryPosition` игнорирует смысл `after`, хранит только счётчик и флаги отказа; тесты повторного позиционирования проверяют два вызова. Неверный порядок при успешных возвратах API остаётся невидимым для этих тестов. Нужны модель конечного состояния и оконный интеграционный прогон.

Положительные изменения относительно 0.1: проверяются безопасные стили и позиционирование, выделены трекеры, объединяются события, геометрия рисунка кэшируется, размеры Taskbar переводятся из DIP, добавлены настройки/темы/сохранение/автозапуск и тесты отказов. Эти изменения не закрывают приёмку Z-order и зарегистрированный дефект fullscreen.

Подготовлено отдельное [ТЗ исправления рамки — план 0.2.1](../doc/GarlandForWindows_0.2.1_FrameFix_SPEC.md): диагностика фактического порядка, прототип owned-overlay, жизненный цикл цели, обработка своих foreground/DPI и регрессия. Установка owner предлагается как базовая стратегия для проверки, а не как уже доказанное исправление. Технические контракты Win32 и ссылки на документацию Microsoft приведены в ТЗ.
